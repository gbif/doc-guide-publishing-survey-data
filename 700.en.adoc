== Mapping Occurrence information

[IMPORTANT]
====
Occurrence information should be saved to the `occurrence` table. 
====

Any DwC Event can be associated with one or more Occurrence records. Occurrence information is mapped using the https://rs.gbif.org/core/dwc_occurrence_2025-07-10.xml[DwC Occurrence extension^] and linked to an Event via the appropriate term:dwc[dwc:eventID]. Each Occurrence record can be linked to only a single survey Event; however, Occurrence records can be linked to any Event level. In the case of a nested hierarchy, the recommended best practice is to link each Occurrence to the lowest possible Event level to maintain specificity. Occurrence information should be contained in the `occurrence` table of the DwC-A.

Each organism Occurrence must include the following information:

* *Event ID (term:dwc[dwc:eventID]):* Links the Occurrence to the correct Event. +
* *Occurrence ID (term:dwc[dwc:occurrenceID]):* A unique identifier for each Occurrence. +
* *Scientific name (term:dwc[dwc:scientificName]):* The most precise (lowest rank) taxonomic identification of the reported organism(s). +
* *Basis of record (term:dwc[dwc:basisOfRecord]):* The nature of the Occurrence record (e.g., `HumanObservation`, `PreservedSpecimen`, `MaterialSample`). See link:#mapping-material-sample-information[Mapping material sample information] for records based on collected specimens and samples.

=== Reporting multiple individuals as a single Occurrence

If multiple individuals of the same taxonomic classification are observed and no additional information about the organisms (e.g., life stage, sex) beyond taxonomic identification is reported, all individuals should be reported as a single Occurrence (e.g., 1 row in the table), with the following information: 

* the term:dwc[dwc:eventID] of the Event when the Occurrence occurred, +
* a unique term:dwc[dwc:occurrenceID], +
* the taxonomic classification of the organisms reported in term:dwc[dwc:scientificName], and +
* the quantity and unit of organisms observed reported in the paired terms term:dwc[dwc:organismQuantity] and term:dwc[dwc:organismQuantityType].

For example, if four hooded crows (_Corvus cornix_) were observed, a single occurrence with one term:dwc[dwc:occurrenceID] should be reported. See the table below.

=== Reporting absences

<<absence, *Absences*>> are defined here as the lack of detection of organisms that are explicitly stated to be part of the target taxonomic scope. Information regarding the absence of detection of a type of taxon can be reported explicitly or implicitly within a DwC-A. 

The reporting of absences only provides meaningful information when taxonomic scope is fully reported (http://rs.tdwg.org/eco/terms/isTaxonomicScopeFullyReported[`eco:isTaxonomicScopeFullyReported`^] = `true`). 

If taxonomic scope is not fully reported (http://rs.tdwg.org/eco/terms/isTaxonomicScopeFullyReported[`eco:isTaxonomicScopeFullyReported`^] = `false`), Occurrence records of zero individuals are uninterpretable because the user of these data cannot know whether there are any taxa that were not detected but were not reported with Occurrence records of zero individuals. Implicit reporting of absences is impossible if taxonomic scope is not fully reported (http://rs.tdwg.org/eco/terms/isTaxonomicScopeFullyReported[`eco:isTaxonomicScopeFullyReported`^] = `false`).

*If absences are implicitly reported*, each end user of data will need to reconstruct explicit absences for themselves for each taxon of interest to them because any unreported taxon (i.e. any taxon without an Occurrence record) is known to be absent. Again, this will only be possible if a taxonomic scope is fully reported (http://rs.tdwg.org/eco/terms/isTaxonomicScopeFullyReported[`eco:isTaxonomicScopeFullyReported`^] = `true`).


*Explicit documentation of absences*

Explicit reporting of absence or non-detection means that the dataset reports, at the Occurrence level (in the `occurrence` table), the lack of detection for each relevant dwc:Taxon. When the taxonomic scope is highly constrained, for example being restricted to only one or a few taxa, it is feasible to include Occurrence records for each of the non-detected taxa within the data, with each absence being denoted by reporting term:dwc[dwc:occurrenceStatus] as `absent` or `notDetected`. To explicitly document taxonomic absences in a DwC-A by including zero-count Occurrence records:

* In the `occurrence` table, for each Occurrence to be reported absent:
** Populate required fields, e.g., term:dwc[dwc:eventID] (refer to the link:#mapping-occurrence-information[list of required Occurrence terms]) +
** term:dwc[dwc:occurrenceStatus] = `absent` or `notDetected`. +
** Recommended best practice is to also populate term:dwc[dwc:individualCount] and term:dwc[dwc:organismQuantity] as `0` and term:dwc[dwc:organismQuantityType] as `individuals`. +
* In the `survey` table:
** If one or more absences are reported at any taxonomic level (term:dwc[dwc:occurrenceStatus] = `absent` or `notDetected`), then http://rs.tdwg.org/eco/terms/isAbsenceReported[`eco:isAbsenceReported`^] = `true` for each relevant Event.
** A list of absent taxa can be provided using http://rs.tdwg.org/eco/terms/absentTaxa[`eco:absentTaxa`^] at all relevant Events. See the section 'link:#absences[Absence]' for details on reporting absence information at the Event level.

Absences should only be reported for taxa within the stated taxonomic and/or organismal scope of a survey. Absence cannot be asserted for bycatch.

*Implicit documentation of absences*

Implicit reporting of absence or non-detection, on the other hand, means that the lack of detection of a dwc:Taxon is indirectly suggested through the lack of Occurrence record in the `occurrence` table. When taxonomic scopes are broader, and include hundreds or thousands of species (e.g., a taxonomic scope of a dataset that includes all species of birds in the world), then it is not feasible to add occurrence records of zero individuals for all of the species not detected. To implicitly document absences in a DwC-A, http://rs.tdwg.org/eco/terms/isTaxonomicScopeFullyReported[`eco:isTaxonomicScopeFullyReported`^] must be `true` for the Event and either http://rs.tdwg.org/eco/terms/targetTaxonomicScope[`eco:targetTaxonomicScope`^] or http://rs.tdwg.org/eco/terms/excludedTaxonomicScope[`eco:excludedTaxonomicScope`^] must be specified. Then:

* In the `occurrence` table, for each taxon to be implicitly reported absent, there will not be any Occurrence record created.
* In the `survey` table, http://rs.tdwg.org/eco/terms/isAbsenceReported[`eco:isAbsenceReported`^] = `false` for all relevant Events because no absences are explicitly reported. See the section 'link:#absences[Absence]' for details on reporting absence information at the Event level.

Absences should only be reported for taxa within the stated taxonomic and/or organismal scope of a survey. Absence cannot be asserted for bycatch.

=== Reporting abundances

To capture <<abundance, abundance>> in a dataset or at a specific Event level:

* In the `occurrence` table, 
** Populate required fields, e.g., term:dwc[dwc:eventID] (refer to the link:#mapping-occurrence-information[list of required Occurrence terms]) +
** use the paired terms term:dwc[dwc:organismQuantity] and term:dwc[dwc:organismQuantityType] to report the observed abundance for each reported Occurrence. For example, if 3 individuals of a species were observed, term:dwc[dwc:organismQuantity] = `3` and term:dwc[dwc:organismQuantityType] = `individuals`.
* In the `survey` table:
** The inclusion of abundance information in the dataset, even if this information is not reported for all taxa, should be indicated by populating http://rs.tdwg.org/eco/terms/isAbundanceReported[`eco:isAbundanceReported`^] as `true`. +
** The existence of an abundance cap should be captured using the Boolean term http://rs.tdwg.org/eco/terms/isAbundanceCapReported[`eco:isAbundanceCapReported`^] and the value of that cap reported in http://rs.tdwg.org/eco/terms/abundanceCap[`eco:abundanceCap`^].

If the dataset or relevant Event does not include abundance information, then it is recommended that the following terms be populated as follows in the `survey` table at the appropriate level(s) within the Event hierarchy:

* http://rs.tdwg.org/eco/terms/isAbundanceReported[`eco:isAbundanceReported`^] = `false` +
* http://rs.tdwg.org/eco/terms/isAbundanceCapReported[`eco:isAbundanceCapReported`^] = `false`

See the section 'link:#abundance-information[Abundance]' for details on reporting abundance information at the Event level.
